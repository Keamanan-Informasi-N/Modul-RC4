# Modul RC4 (Rivest Cipher 4)

RC4 is a symmetric-key **stream cipher** designed by Ron Rivest in 1987. Unlike DES, it does not process fixed-size blocks; it generates a pseudo-random keystream and XORs it with the data byte by byte.

- The key is variable length, from 1 to 256 bytes.
- The internal state is a 256-byte permutation array `S`.
- Encryption and decryption are the same operation: `output = input XOR keystream`.
- No block modes (ECB/CBC), IV, or padding are needed, since the output length equals the input length.

---

## RC4 Scheme

```text
Key
 |
 v
KSA (Key-Scheduling Algorithm)
 |
 v
State S (256 bytes)
 |
 v
PRGA (Pseudo-Random Generation Algorithm)
 |
 v
Keystream K
 |
Plaintext XOR K -> Ciphertext
```

---

## Key-Scheduling Algorithm (KSA)

`S` is initialised to the identity permutation `[0, 1, ..., 255]`, then shuffled using the key.

```text
for i = 0 to 255:
    S[i] = i

j = 0
for i = 0 to 255:
    j = (j + S[i] + key[i mod keylength]) mod 256
    swap(S[i], S[j])
```

---

## Pseudo-Random Generation Algorithm (PRGA)

For each byte of data, one keystream byte is produced while the state keeps being shuffled.

```text
i = 0, j = 0
for each byte:
    i = (i + 1) mod 256
    j = (j + S[i]) mod 256
    swap(S[i], S[j])
    K = S[(S[i] + S[j]) mod 256]
```

---

## Encryption and Decryption

```text
Encryption: C = P XOR K

Decryption: P = C XOR K
```

Because XOR is its own inverse, the same keystream recovers the plaintext. The same key must never be reused for two different messages, otherwise `C1 XOR C2 = P1 XOR P2` leaks information.

## Usage

All files contain hex strings, same as the DES module.

```text
python RC4.py --enc <key> <input> <output>
python RC4.py --dec <key> <input> <output>
```

`--enc` and `--dec` perform the identical operation and are kept only for interface parity with the DES module.

Example (test vector, key = `Key`, plaintext = `Plaintext`):

```text
key.txt:    4B6579
input.txt:  506C61696E74657874
output.txt: BBF316E8D940AF0AD3
```

## Security and Deprecation

RC4 is considered broken and should not be used for new systems. This module is for learning only.

### Known weaknesses

- **Biased keystream:** the first bytes of the keystream are not uniformly random and leak information about the key.
- **FMS attack (2001):** exploits weak keys and related key material to recover the key from many encrypted packets. It broke WEP Wi-Fi, since WEP prepends a public IV to the key.
- **Bar Mitzvah attack (2015):** exploits weak keys generated by the SSL keying process to recover plaintext.
- **NOMORE attack (2015):** exploits the Fluhrer-McGrew biases against TLS and WPA/TKIP.
- **Stream cipher reuse:** no IV or nonce is built in, so reusing a key for two messages leaks `P1 XOR P2`.

### Removal from software and operating systems

| Year | Change |
|------|--------|
| 2013 | Microsoft Security Advisory 2868725 recommends disabling RC4 |
| 2015 | IETF RFC 7465 prohibits RC4 cipher suites in TLS |
| 2016 | Firefox 44 disables RC4; Microsoft Edge and IE11 drop RC4 (KB3151631); Chrome removes it in the same period |
| 2026 | Windows Kerberos moves away from RC4 in three phases (below) |

Windows Kerberos timeline (from Microsoft's update rollout, as reported by third-party sources):

- **13 Jan 2026:** audit events for RC4 usage are added.
- **14 Apr 2026:** default becomes AES-only when an account's encryption types are unset; rollback still possible.
- **14 Jul 2026:** rollback removed and enforcement is permanent.

The main driver for Kerberos is **Kerberoasting**: any domain user can request a service ticket encrypted with the service account's key, then brute-force the password offline. RC4 tickets are much faster to crack than AES.

On Windows, RC4 can also be turned off in Schannel through the registry by setting `Enabled` to `0` for each RC4 key length.

### Modern replacements

- **AES-GCM** or **ChaCha20-Poly1305** for authenticated encryption.
- **AES-CTR** if only a stream-like mode is needed.
